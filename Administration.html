規劃每個邊界: 透過工作區控制授予目標對象 Codex cloud 存取權, 安裝並設定來源系統整合, 限制來源系統中的儲存庫存取, 設定雲端環境, 密鑰與網際網路存取, 設定選用的代管工作流程如程式碼審查, 並用具代表性的使用者測試。

把外掛安裝, 內建 skills, 應用程式支援能力, 應用程式動作與來源系統授權視為各自獨立的決策, 納入外掛或 skill 前先確認來源, 負責人, 目標對象與審查日期。

選擇符合你問題的報表介面: 工作區分析, Analytics API, Compliance API, 或使用限制與支出控制, 並將 API 金鑰儲存在組織的密鑰管理系統中。

用具代表性的身分驗證每一個適用的邊界, 記錄每項控制的負責人與目前的程序來源, 初次導入後檢視存取權, 已連接能力, 額度使用, 支援回饋與實際工作流程, 並依訊號變化調整範圍與指引。

Groups and provisioning

了解群組成員來源與其工作區存取邊界, 群組用來組織一組成員的 ChatGPT 工作區存取權, 並可攜帶自訂角色, 群組成員資格與本機執行政策及已連接系統中的權限是分開的。

Manually managed

成員資格來源為 ChatGPT 工作區管理介面, 適合群組較小, 臨時性, 或未透過目錄同步管理時。

Identity-provider managed

成員資格來源為你的身分提供者, 透過 SCIM 同步, 適合成員資格應遵循組織目錄與成員移除流程時。

SCIM 佈建工作區成員資格與群組指派, 但不會授予 GitHub, Google Drive, Slack 或其他已連接系統中的權限, 也不會取代本機執行需求或 Platform API 組織存取權。

Roles and workspace permissions

把 ChatGPT 工作區存取與本機執行, API, 外掛及來源系統控制分開來看, 管理涵蓋六個控制邊界, 在其中一個邊界獲得存取權不代表在另一個邊界也有存取權。

Managed Configuration

在受支援的本機用戶端上強制執行執行時期需求, 並發佈受管理的預設值。管理員可用兩種方式控制本機用戶端行為: requirements 是使用者無法覆寫的強制約束, managed defaults 是用戶端啟動時套用的起始值, 使用者仍可在執行期間變更, 但下次啟動時會重新套用。

requirements.toml 範例

權限設定檔 功能旗標 拒絕讀取 受管理 Hooks 指令規則 MCP 伺服器限制
default_permissions = ":workspace" [allowed_permission_profiles] ":read-only" = true ":workspace" = true # ":danger-full-access" 未列出, 因此被拒絕

用 allowed_permission_profiles 控制使用者可選擇的內建與自訂權限設定檔, 需要 Codex 0.138.0 以上版本。

[features] browser_use = false browser_use_full_cdp_access = false browser_use_external = false in_app_browser = false computer_use = false

可跨瀏覽器與桌面介面停用 Computer Use, 若省略這些鍵, 政策不限制該功能, 一般的產品可用性規則仍適用。

[permissions.filesystem] deny_read = [ "/**/*.env", "~/.ssh", ]

管理員可用絕對路徑或 glob 樣式拒絕讀取特定路徑, 使用者無法用本機設定弱化這項需求。

allow_managed_hooks_only = true [features] hooks = true [hooks] managed_dir = "/enterprise/hooks"

管理員可在 requirements.toml 中直接定義受管理的生命週期 hooks, 並用 allow_managed_hooks_only 跳過使用者, 專案, 工作階段與外掛層級的 hooks。

[rules] prefix_rules = [ { pattern = [{ token = "rm" }], decision = "forbidden", justification = "Use git clean -fd instead." }, ]

需求規則會與一般 .rules 檔案合併, 最嚴格的判斷會勝出, decision 只能是 prompt 或 forbidden。

[mcp_servers.docs] identity = { command = "codex-mcp" }

用允許清單限制本機用戶端可啟用哪些 MCP 伺服器, 若 mcp_servers 存在但為空, 用戶端會停用所有 MCP 伺服器。

設定的優先順序

層級順序
macOS 受管理偏好設定 (MDM)最高優先
雲端管理需求 (登入 ChatGPT 時傳送)次高
系統 requirements.toml再次
managed_config.toml覆蓋使用者設定
使用者 config.toml最低優先

CLI 的 --config 覆寫套用在基礎層, 但受管理層仍會覆蓋它們, 這代表即使提供本機旗標, 每次執行仍會從受管理的預設值開始。

Skill controls

Skills 是由指示與支援資源組成的可重複使用工作流程, ChatGPT 工作區 Skills, 本機檔案系統 skills 與封裝 skills 的外掛擁有各自獨立的生命週期與存取控制。

Deploy the Windows app

為 Windows 版 ChatGPT 桌面應用程式選擇企業安裝與更新路徑, 依據誰控制安裝與更新以及你的網路是否允許微軟應用程式散布服務來選擇部署方式。

情境部署路徑
使用者自行安裝與更新使用 web installer
IT 部署且微軟更新服務可用透過 Intune 等工具部署 Microsoft Store 應用程式
IT 控制更新時機或封鎖微軟更新服務透過軟體管理流程重新部署每個新版本
網路封鎖微軟應用程式散布服務使用限制網路適用的離線 MSIX 套件
winget install --id 9PLM9XGG6VKS -s msstore

延後更新是安全性與穩定性的取捨, 因為應用程式包含會定期更新的瀏覽器與執行環境元件, 建議每次 Codex 發布都重新部署, 至少每週檢查一次新版本。

在想連接的主機上打開應用程式, 於側邊欄選擇 Set up Remote。

用手機掃描應用程式顯示的 QR code。

ChatGPT 開啟 Remote 設定流程, 確認相同的帳號與工作區, 完成所需的多重要素驗證, SSO 或 passkey 步驟。

在主機的應用程式中用 Settings > Connections 管理已連接裝置。

步驟 1 / 4

疑難排解

手機看不到主機 重新登入後 Remote Control 關閉 核准請求沒有出現 遠端工作階段斷線

確認桌面應用程式在主機上執行中, 已啟用 Allow other devices to connect, 且兩台裝置使用相同的 ChatGPT 帳號與工作區。

登出 ChatGPT 會關閉 Remote Control, 但不會移除既有的裝置配對。

在 ChatGPT 行動應用程式打開 Remote, 若使用工作區, 請管理員確認已啟用 Remote Control 存取權。

檢查主機是否進入睡眠, 失去網路連線或關閉應用程式, 保持主機喚醒並連線。

Use Codex with Amazon Bedrock

設定 Codex 使用透過 Amazon Bedrock 提供的 OpenAI 模型, Codex 可在本機執行, 並用 AWS 管理的驗證與存取控制把模型請求送往 Bedrock。

model_provider = "amazon-bedrock"

此設定僅涵蓋商用 AWS 地區的 Amazon Bedrock Mantle 路徑, 不支援 GovCloud 地區。

驗證選項

Bedrock API key
export AWS_BEARER_TOKEN_BEDROCK=<key> export AWS_REGION=us-east-2
AWS SDK credentials

使用標準 AWS SDK 憑證來源: aws configure 的共享設定檔, 環境變數, aws login, AWS SSO 或具名 profile, 或 credential_process 的聯合身分。

功能可用性

可用

本機程式碼審查, auto-review, sandboxing, 排程任務, Git 工具, 本機環境, appshots, 部分瀏覽器與 Computer Use 功能, 自訂指示, skills, 本機外掛, MCP, subagents。

不可用

Codex cloud, 雲端任務, 圖片生成, 語音聽寫, 網頁搜尋, 外掛分享, connectors, memories, chronicle, sites, GitHub 整合, Slack/Linear 整合, enterprise SSO, analytics, Codex Security。

疑難排解

確認模型 ID
完全符合支援的模型 ID, 例如 openai.gpt-5.5。
確認地區支援
AWS 地區支援所選模型。
確認憑證有效
Bedrock API 金鑰或 AWS 憑證有效且未過期。
確認環境變數
桌面應用程式或 VS Code 使用者需將環境變數放在 ~/.codex/.env 中。

OpenAI 支援協助 Codex 用戶端設定與本機行為, AWS 憑證, IAM 權限, Bedrock 存取或帳單問題請聯繫你的 AWS 管理員或 AWS 支援。
