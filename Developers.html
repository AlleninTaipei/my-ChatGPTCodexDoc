ChatGPT 與 Codex 開發者指南

涵蓋程式碼審查, Hooks, plugins, SDK, app-server 協定與 CLI 完整參考的技術文件, 提供可搜尋與可互動探索的介面。

Code Review

在 ChatGPT 與 Codex 各用戶端之間審查程式碼變更。在 ChatGPT Work 中上傳程式碼供審查, 或透過已安裝的來源外掛提供, 在提示中指名 pull request, 分支, commit, 檔案與審查準則。

在各介面中發起審查

桌面應用程式

打開審查面板了解變更內容, 給予行級意見, 決定要暫存, 還原, 提交或推送哪些內容。輸入框輸入 /review, 選擇 Review against a base branch 或 Review uncommitted changes。

CLI

輸入 /review 開啟 CLI 審查預設集, Codex 啟動專屬的審查器讀取所選 diff, 回報有優先順序且可執行的發現, 不會變更你的工作目錄。

IDE 擴充功能

在輸入框輸入 /review, 選擇 Review against a base branch 或 Review uncommitted changes, /review 只有在開啟的專案位於 Git 儲存庫內時才會出現。

選擇審查範圍

Review against a base branch
找出合併基準點並審查你的分支 diff。
Review uncommitted changes
包含已暫存, 未暫存與未追蹤的檔案。
Review a commit
審查指定 commit 的確切變更集合。
Custom review instructions
依你提供的準則聚焦審查重點。

審查面板反映的是你 Git 儲存庫的狀態, 而非只有 Codex 編輯的內容, 預設顯示 Unstaged, 也可切換 Staged, Commit, Branch 或 Last turn。

暫存與還原檔案

Entire diff
使用審查標頭中的 Stage all 或 Revert all。
Per file
對單一檔案暫存, 取消暫存或還原。
Per hunk
對單一 hunk 暫存, 取消暫存或還原。

Pull request 審查流程

1 · 開啟審查面板
在 pull request 分支上開啟審查面板。
2 · 檢視情境
檢視 pull request 情境, 意見與已變更檔案。
3 · 請求修復
請 Codex 修復你想處理的特定意見。
4 · 檢視結果
在審查面板檢視產生的 diff。
5 · 推送
準備好後, 暫存, 提交並推送到 pull request 分支。

安裝並用 gh auth login 驗證 GitHub CLI, Codex 才能載入 pull request 情境, 審查意見與已變更檔案。

Integrated Terminal

不離開任務就能執行指令並檢視輸出, 桌面應用程式中每個任務都包含限定於目前專案或 worktree 的終端機, 從右上角終端機圖示開啟, 或按 Ctrl+`。

git status
檢查目前變更狀態。
git pull --rebase
同步遠端變更。
pnpm test / npm test
執行測試。
pnpm run lint
執行專案特定檢查。

ChatGPT 可以讀取目前的終端機輸出, 因此能在與你協作時檢查執行中的開發伺服器或參考失敗的建置紀錄。若常執行某個指令, 在本機環境中定義一個 action, 會以捷徑形式出現在桌面應用程式中, 並在整合終端機執行, Cmd+K 開啟指令面板但不會清除終端機, 清除終端機請按 Ctrl+L。

Build skills

用 agent skills 賦予 Codex 新的能力與專長, 一個 skill 封裝指示, 資源與選擇性腳本, 讓 Codex 能可靠地遵循某個工作流程, skills 以開放的 agent skills 標準為基礎, 可打包成 plugins 分發給 ChatGPT Work 與桌面應用程式。

Codex 如何使用 skills

明確呼叫

在提示中用 /skills 或 $ 直接提及 skill。

隱含呼叫

當你的任務符合 skill 描述時, Codex 自動選用該 skill, 有效的描述應精簡, 把關鍵使用情境放在前面, 並包含觸發詞以利比對。

建立與尋找位置

用 $skill-creator 內建建立工具, 引導你定義 skill 的功能與觸發時機, 或建立一個含 SKILL.md 檔案並附上 name 與 description frontmatter 的資料夾。Skills 會從儲存庫層級 (.agents/skills), 使用者層級 ($HOME/.agents/skills), 管理員層級 (/etc/codex/skills) 與系統層級發現。

讓每個 skill 聚焦單一任務, 優先使用指示而非腳本, 除非需要確定性行為, 撰寫具明確輸入輸出的命令式步驟, 並用實際提示測試 skill 描述能否正確觸發。

Build plugins

建立, 測試並分發 ChatGPT 的 plugins。本文件面向 plugin 作者, 單一儲存庫或個人工作流程建議先從本機 skills 開始, 需要跨團隊分享工作流程, 封裝連接器或 MCP 設定, 打包生命週期 hooks, 或發布穩定套件時建立 plugin。

用 @plugin-creator 快速建立

內建的 @plugin-creator skill 提供最快的設定路徑, 會自動產生所需的 .codex-plugin/plugin.json 清單並產生用於測試的本機市集項目。

$plugin-creator create a Codex plugin for my ChatGPT app. Use plugin_asdk_app_6a4c0062f3b88191855c0a80eac5d53d and name it Acme Support. Include a personal marketplace entry so I can test it locally.

分享與停用

安裝並在 Work 或 Codex 中建立 plugin 後, 從桌面應用程式的 Plugins 中選擇 Created by you, 開啟詳細頁面選擇 Share, 加入工作區成員, 群組, 或複製分享連結。工作區管理員可在 requirements.toml 加入 features.plugin_sharing = false 停用分享。

Build an app

建置 plugin 中由 MCP 支援的 app 部分, 可選擇性搭配 Apps SDK 提供的 UI。Apps SDK 是用於 MCP 支援 app 的 ChatGPT 應用程式開發框架, 建立在 MCP 之上, 你的伺服器公開工具並回傳結構化資料。

App 可以包含的部分

MCP 伺服器

定義工具, 處理驗證, 回傳結構化資料, 並強制執行整合的實際行為。

選擇性 MCP UI

當使用者需要在 ChatGPT 中檢視, 比較, 編輯, 確認或導覽結構化資訊時才需要, 若工具呼叫與模型回應已足夠, 不需要自訂 UI。

先建立 MCP, 再視需要加入 UI

1 · 找出工作流程
識別 app 應支援的使用者工作流程。
2 · 定義工具
定義這些工作流程所需的 MCP 工具。
3 · 撰寫清楚的描述
寫出清楚的工具名稱, 描述, 輸入與輸出 schema。
4 · 標記安全註記
為每個工具標記準確的安全註記, 再檢視安全與隱私指引。
5 · 加入驗證
只為需要的資料或動作加入驗證。
6 · 開發模式測試
在打包成 plugin 前, 於 ChatGPT 開發模式測試 app。

即使加入 UI, 也要讓工具與渲染層保持解耦, 工具仍應回傳有用的結構化資料與模型可讀結果, UI 元件則專注於呈現與互動。

Hooks

在 Codex 生命週期中執行確定性腳本。Hooks 是 Codex 的擴充框架, 讓開發者把自訂腳本注入代理迴圈, 可用於傳送對話到自訂記錄系統, 掃描不慎貼上的 API 金鑰, 自動從對話建立持久記憶, 在回合完成時執行驗證檢查, 依目錄情境自訂提示。

執行行為與發現位置

並行執行
同一事件的多個相符 hooks 會同時啟動, 避免互相阻擋。
信任審查
非受管理的指令 hooks 需要先審查與信任才能執行, 系統依 hook 的雜湊值記錄信任狀態。
回合範圍
PreToolUse, PermissionRequest, PostToolUse, PreCompact, PostCompact, UserPromptSubmit, SubagentStop, Stop 於回合範圍運作。
工作階段範圍
SessionStart, SubagentStart 於執行緒或子代理啟動範圍運作。
發現位置
~/.codex/hooks.json
~/.codex/config.toml
<repo>/.codex/hooks.json
<repo>/.codex/config.toml

事件參考

SessionStart SubagentStart PreToolUse PermissionRequest PostToolUse PreCompact / PostCompact UserPromptSubmit SubagentStop Stop

工作階段開始時執行, matcher 依 source 篩選 (startup, resume, clear, compact)。JSON 輸出可加入 hookSpecificOutput.additionalContext 補充開發情境。

{ "hookSpecificOutput": { "hookEventName": "SessionStart", "additionalContext": "Load the workspace conventions before editing." } }

子代理開始時執行, matcher 依 agent_type 篩選, 輸入含 turn_id, agent_id, agent_type, permission_mode。

攔截 Bash, apply_patch 與 MCP 工具呼叫, matcher 依 tool_name 篩選, 可拒絕, 改寫或補充情境。

{ "hookSpecificOutput": { "hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": "Destructive command blocked by hook." } }

當 Codex 需要核准時執行, matcher 依 tool_name 篩選, 若多個 hooks 決策, deny 優先於其他決定。

{ "hookSpecificOutput": { "hookEventName": "PermissionRequest", "decision": { "behavior": "deny", "message": "Blocked by repository policy." } } }

Bash, apply_patch 與 MCP 工具產生輸出後執行, 可在提供回饋的同時阻擋後續處理。

PreCompact 於對話壓縮前執行, PostCompact 於壓縮後執行, matcher 都依 trigger 篩選 (manual, auto), 回傳 continue: false 可阻止或於壓縮後停止。

使用者送出提示時執行, 不使用 matcher, 可補充開發情境或以 decision: "block" 阻擋。

子代理停止時執行, matcher 依 agent_type 篩選, 任何相符 hook 回傳 continue: false 會阻止其他 hooks 繼續該子代理。

回合完成時執行, 不使用 matcher, decision: "block" 會用 reason 作為自動延續提示繼續執行。

Matcher 樣式與管理

matcher 欄位使用正規表示式篩選 hooks 何時啟動, 用 "*", "" 或省略以符合全部事件, 例如 Bash, ^apply_patch$, Edit|Write, mcp__filesystem__.*。在 config.toml 設定 [features] hooks = false 可停用 hooks, 管理員可透過 requirements.toml 強制設定, 並用 allow_managed_hooks_only = true 只載入受管理 hooks。

Codex environments

選擇 Codex 任務在哪裡執行, 以及檔案如何被隔離。在桌面應用程式的 ChatGPT 下拉選單選擇 Codex, 開始任務時可選擇執行位置。

Local

直接在你目前的專案目錄中工作。

Worktree

在 Git worktree 中隔離變更。

Cloud

在已設定的雲端環境中遠端執行。

Local 與 Worktree 任務都在你的電腦上執行。

Local environments

為 worktree 設定常用動作與初始化腳本, 只限桌面應用程式中的 Codex 使用, 設定會保存在專案根目錄的 .codex 資料夾中, 可納入版控與團隊共享。

Setup scripts
Codex 建立新 worktree 時自動執行, 用於安裝相依套件或建置流程。
Actions
定義常用操作如啟動開發伺服器或執行測試, 出現在工具列並於整合終端機執行。
內建 Git 工具
Diff 檢視顯示目前變更並支援行內意見, 可暫存, 還原, 提交, 推送分支或開啟 pull request。
# TypeScript 專案範例 npm install npm run build

Cloud environments

自訂 Codex 在雲端任務中安裝與執行的內容, 例如加入相依套件, 安裝 linter 與格式化工具, 設定環境變數。

雲端任務如何執行

1 · 建立容器
2 · 執行設定腳本
3 · 套用網路設定
4 · 迴圈執行
5 · 顯示結果

Codex 建立容器並在選定的分支或 commit SHA 簽出你的儲存庫。

執行設定腳本, 以及快取容器恢復時的選擇性維護腳本。

套用網際網路存取設定, 設定腳本階段有網路存取, 代理階段預設關閉但可設定有限或無限制存取。

代理在迴圈中執行終端機指令, 編輯程式碼, 執行檢查並嘗試驗證工作成果, 若儲存庫含 AGENTS.md 會用它找出專案特定的檢查與測試指令。

代理完成後顯示答案與變更檔案的 diff, 你可以開啟 PR 或提出後續問題。

步驟 1 / 5

環境變數與 Secrets

環境變數

在整個任務期間都有效, 包含設定腳本與代理階段。

Secrets

與環境變數類似但多一層加密, 只在任務執行時解密, 只提供給設定腳本使用, 代理階段開始前會被移除。

Codex 會快取容器狀態最多 12 小時以加速新任務與後續請求, 若變更設定腳本, 環境變數或 secrets 會自動使快取失效, 也可以在環境頁面手動選擇 Reset cache。

Worktrees

Worktrees 讓 Codex 能在同一個專案中執行多個獨立任務而互不干擾, 對排程任務在專屬背景 worktree 中運作特別有用, 建立在 Git 的 worktree 功能之上, 建立第二份儲存庫副本並共享 Git 中繼資料。

Local checkout
你原本的儲存庫。
Worktree
應用程式內從本機簽出建立的 Git worktree。
Handoff
在 Local 與 Worktree 環境之間搬移任務的流程。
平行工作
不打擾目前 Local 設定的情況下平行工作。
排隊背景任務
在保持前景專注的同時排隊背景任務。
轉移至 Local
把任務轉移到 Local 進行檢查或協作。

Codex 在 $CODEX_HOME/worktrees 中維護受管理的 worktree, 預設保留最近 15 個, .worktreeinclude 檔案可指定需複製到新 worktree 的忽略檔案, 例如環境設定檔。

Codex SDK

以程式化方式控制本機 Codex 代理, 適用於 CI/CD 流程, 建立能與 Codex 互動的自訂代理, 或把 Codex 整合進自己的應用程式與工具中。

TypeScript 與 Python 函式庫

TypeScript, 伺服器端, Node.js 18+
import { Codex } from "@openai/codex-sdk"; const codex = new Codex(); const thread = codex.startThread(); const result = await thread.run( "Make a plan to diagnose and fix the CI failures" );
Python, Python 3.10+
from openai_codex import Codex, Sandbox with Codex() as codex: thread = codex.thread_start( model="gpt-5.4", sandbox=Sandbox.workspace_write, ) result = thread.run("Make a plan...")

Sandbox presets

Sandbox.read_only
讀取檔案, 不允許寫入。
Sandbox.workspace_write

Sandbox.full_access

Codex App Server

透過 app-server 協定把 Codex 嵌入你的產品, 這是 Codex 用於驅動豐富用戶端 (例如 Codex VS Code 擴充功能) 的介面, 適合需要驗證, 對話歷程, 核准與串流代理事件的深度整合, 實作已在 Codex GitHub 儲存庫開源。

傳輸方式說明
stdio, 預設--listen stdio://, 換行分隔的 JSON (JSONL)。
websocket, 實驗性--listen ws://IP:PORT, 每個 WebSocket 文字訊框一則 JSON-RPC 訊息。
Unix socket--listen unix:// 或 unix://PATH, 使用標準 HTTP Upgrade 交握。
off--listen off, 不公開本機傳輸。
# 啟動監聽 codex app-server --listen ws://127.0.0.1:4500 # 連接終端機介面 codex --remote ws://127.0.0.1:4500

核心元件

Thread
使用者與 Codex 代理之間的對話, 內含多個 turn。
Turn
一次使用者請求與後續的代理工作, 內含多個 item 並串流增量更新。
Item
輸入或輸出的單位, 例如使用者訊息, 代理訊息, 指令執行, 檔案變更, 工具呼叫。

事件與 Items

啟動或恢復執行緒後, 持續讀取傳輸串流上的通知, 包含 thread/started, thread/archived, turn/started, turn/completed, turn/diff/updated, turn/plan/updated 與各種 item/* 事件。ThreadItem 常見型別包含 userMessage, agentMessage, plan, reasoning, commandExecution, fileChange, mcpToolCall, webSearch, enteredReviewMode, exitedReviewMode, contextCompaction, 每個 item 都會發出 item/started 與 item/completed 兩個生命週期事件。

核准流程

指令執行核准依序為 item/started, item/commandExecution/requestApproval, 用戶端回應 accept/acceptForSession/decline/cancel, serverRequest/resolved, 最後 item/completed。檔案變更核准流程類似, 使用 item/fileChange/requestApproval。內建的 request_permissions 工具會送出 item/permissions/requestApproval, 回應時只包含授予的權限子集, scope 設為 session 可讓授權延續到同一工作階段的後續回合。

safety-strategy, 預設 drop-sudo
在執行 Codex 前移除 sudo。
unprivileged-user

read-only
防止檔案變更與網路存取。
allow-users / allow-bots
限制可觸發工作流程的對象。

資安檢查清單

限制觸發者
用受信任的事件或明確核准限制誰能啟動工作流程。
清理輸入
清理來自 pull request 與 commit 訊息的提示輸入, 避免注入。
保護金鑰
保持 safety-strategy 為 drop-sudo, 或使用非特權使用者。
最後執行
把 Codex 放在最後一個步驟, 避免後續步驟繼承非預期變更。

常見用法

--ephemeral
避免把工作階段紀錄檔持久化到磁碟。
--sandbox workspace-write
允許編輯, 建議取代已淘汰的 --full-auto。
--output-schema
要求最終回應符合指定的 JSON Schema。

把最終訊息寫入檔案供下游腳本使用。

Prompt-plus-stdin

常用指令範例

codex exec codex review codex mcp codex sandbox codex cloud

--ephemeral 不持久化紀錄檔, --sandbox 選擇沙箱政策, --json 印出 JSON Lines 事件, --output-schema 限制回應格式, resume 子指令可延續先前的非互動工作階段。

--uncommitted 審查未提交變更, --base 與基準分支比較, --commit 審查指定 commit, 三者與自訂 PROMPT 互斥, --title 只能搭配 --commit 使用。

add 用 stdio 啟動指令或 --url 註冊 streamable HTTP 伺服器, get/list 檢視設定, login/logout 只適用於支援 OAuth 的 streamable HTTP 伺服器。

在 Codex 內部使用的相同政策下執行指令, macOS 用 Seatbelt, Linux 用 Landlock, 皆支援 --permission-profile 套用具名權限設定檔。

--env 指定雲端環境, --attempts 設定 best-of-N 嘗試次數, codex cloud list 以 --json 列出近期任務供自動化使用。

Developer settings

跨 ChatGPT 與 Codex 用戶端設定開發選項。

ChatGPT web
在 ChatGPT 設定中儲存產品與工作區偏好, Work 對話在受管理環境中執行, 不會讀取本機 Codex 設定檔。
Code review
在 Settings > Git 中用 Review delivery 選擇 Inline 於目前任務執行 /review, 或 Detached 開始獨立審查任務。
IDE extension sync
桌面應用程式與 IDE 擴充功能在同一專案開啟時共享作用中任務與編輯器情境, 可從輸入框開關 IDE context。
Git
標準化分支命名, 選擇是否使用強制推送, 設定產生提交訊息與 pull request 描述的提示。
Codex CLI
從 ~/.codex/config.toml 讀取個人預設值, 需要專案特定覆寫時在受信任的專案加入 .codex/config.toml。

檢視你的設定

/status
查看作用中的模型, 核准政策, 可寫入根目錄與 token 使用量。
/debug-config
依優先順序查看設定分層, 以及受管理政策需求的來源。
--strict-config
把無法識別的 config.toml 鍵值視為錯誤而非忽略。

設定預設值說明
