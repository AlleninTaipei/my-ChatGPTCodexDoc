ChatGPT 與 Codex 功能指南

從專案與任務管理, 到瀏覽器, Computer Use, 檔案處理與各項系統設定, 一份可互動探索的完整功能說明文件。

Projects, chats, and tasks

在 ChatGPT 中把相關對話, 任務, 檔案與來源放在一起。

要不要建立專案

建立專案

當工作會持續進行, 會產生一個以上的成果, 或依賴相同的檔案與來源時, 建立一個專案。

不建立專案

當工作是獨立且不需要共享專案情境時, 直接開始一個沒有專案的任務。

使用專案把相關對話, 檔案, 指示與來源放在一起, 同一個專案可以同時包含用 Chat 與 ChatGPT Work 開始的對話。

每個專案的結構

Chats
放置對話的區塊。
Sources
放置上傳檔案與已連接情境的區塊, 專案指示會套用到其中所有對話。

ChatGPT 專案不會直接存取你電腦上的資料夾, 因此需要上傳或連接你想讓 ChatGPT 使用的來源。Chat 與 Work 只是改變 ChatGPT 處理請求的方式, 不會改變對話的名稱。

在不同環境中工作

Codex CLI

把你啟動它的目錄視為任務的專案, 從想讓 Codex 工作的目錄執行 codex, 或傳入 --cd <directory> (-C) 明確指定, CLI 不會顯示 ChatGPT Projects 檢視畫面。

IDE Extension

把 IDE 中開啟的資料夾或工作區視為本機專案, 在多根工作區中, 為任務選擇工作區根目錄, 擴充功能不會顯示網頁版或桌面版的 ChatGPT Projects 檢視畫面。

整理專案與任務

釘選專案
讓專案保持在側邊欄上方, 也可以從 Projects 檢視畫面釘選。
釘選任務
當你經常回到某個任務時釘選它, 即使專案中出現更新的任務。
重新命名任務
用能描述結果的簡短標題重新命名, 例如 Q3 launch brief。
搜尋專案
從 Projects 檢視畫面搜尋, 或按 Cmd/Ctrl+G 搜尋過去的任務。
封存任務
完成工作後封存, 從專案選單選擇 Archive tasks 可一次封存多項任務。

釘選不會加入情境或改變 ChatGPT 可存取的內容, 只會改變專案或任務在側邊欄中出現的位置, 已封存的任務可從 Settings > Archived tasks 還原。

用本機專案處理資料夾與程式碼庫

當 ChatGPT 需要讀取或修改你電腦上某個資料夾中的檔案時, 加入一個本機專案, 對程式碼庫而言, 專案資料夾會成為 Codex 任務的工作目錄。若一個儲存庫包含一個以上的應用程式或套件, 在每項任務只該存取其中一部分時, 使用不同的本機專案, 讓工作情境保持聚焦, 使用本機環境定義專案的設定動作與常用指令。想把程式碼變更與目前的簽出隔離時, 選擇 Codex 並在 worktree 中開始任務, 專案與 worktree 用來組織工作, 而 sandbox 則負責限制本機指令能讀取, 變更或存取哪些網路內容。

不建立專案開始任務

當工作是獨立且不需要共享的專案檔案, 指示或資料夾存取權時, 選擇 New task, 當多項任務會依賴相同情境時, 先建立一個專案。

帶入其他工具與情境

參照編輯器內容
參照已開啟的檔案或選取編輯器中的程式碼, 為目前回合加入情境。
設定 MCP 伺服器

使用記憶

Visualizations

在 ChatGPT 中把想法與資訊轉換成互動式視覺解說。Visualizations 可以把問題, 想法與資訊轉換成圖表, 地圖, 圖解, 計算器, 模擬與互動說明, 適合在調整輸入或理解關係能讓答案更清楚, 便於比較, 支援練習或協助行動時使用。

目前各介面的可用狀態

介面狀態
ChatGPT on the web在 Chat 與 ChatGPT Work 中對符合資格的帳號開放
ChatGPT desktop app以預覽形式逐步推出
ChatGPT mobile apps逐步推出給符合資格的帳號, 輸入框控制項依應用程式版本而異
Codex CLI and IDE extension不支援視覺化渲染

桌面版於輸入框輸入 @ 並鍵入 Visualize, 在 Plugins 底下選擇 Visualize；網頁版做法相同, 或直接輸入 @Visualize 並選擇對應建議。

互動範例

Spirograph Wave interference Tokenizer explainer

建立一個互動式 spirograph 說明滾動圓的運作原理, 調整半徑, 筆尖距離與動畫速度, 觀察滾動的圓如何以下列方程式描繪曲線。

x = (R-r)cos(t) + d cos(((R-r)/r)t) y = (R-r)sin(t) - d sin(((R-r)/r)t)

互動式實驗學習單, 用於調整波源並探查干涉場, 修改波長, 波源間距與相位偏移, 同時記錄關於節點樣式與亮帶位置的觀察。

互動展示 GPT 分詞流程: 文字轉 UTF-8 位元組, 轉排序後的位元組對合併, 轉整數 token ID, 使用教學用詞彙表編輯文字並逐步檢視分詞階段 (實際模型使用不同的詞彙表與 ID)。

精修結果

增減控制項
加入或移除控制項, 篩選, 比較或註解。
修正來源資料
修正來源資料, 單位, 標籤或假設。
簡化緩慢結果
用彙整, 分箱或取樣簡化速度過慢的結果。
確保鍵盤可及性
加入文字摘要與資料表格, 確保鍵盤可及性並具備可見的焦點狀態。

疑難排解

視覺化可能需要一分鐘或更長時間產生, 若結果空白或缺漏, 先等待回應完成, 重新載入對話一次, 再重試請求, 若問題持續, 要求更簡單的視覺化, 對大型資料集進行彙整, 分箱, 降採樣或降低精確度, 或改用圖表, 圖解, 表格或 Sites。

套用與一般 ChatGPT 對話相同的資料處理判斷, 只有在組織允許的情況下才納入敏感資訊, 分享前先審視完整對話。

Scheduled tasks

排程重複性任務在背景執行, 在 Scheduled 中檢視進行中, 已暫停與已完成的任務與近期執行紀錄, 你可以把排程任務與 skills 結合處理更複雜的工作。

排程任務清單範例

Daily inbox summary
每個平日上午 8:00, 下次執行於 16 小時後。
Weekly project update
每週五下午 4:00, 下次執行於 2 天後。
Meeting follow-up reminders
每天下午 5:00, 下次執行於 4 小時後。

Sandbox 模式與排程任務的風險

Read-only

若需要修改檔案, 存取網路或操作電腦上的應用程式, 工具呼叫會失敗, 可考慮改為 workspace write。

Workspace-write

若需要修改工作區以外的檔案, 存取網路或操作應用程式, 工具呼叫會失敗, 可用規則選擇性允許特定指令在沙箱外執行。

Full access

背景排程任務風險較高, 因為 ChatGPT 可能在未詢問的情況下變更檔案, 執行指令並存取網路, 建議改為 workspace write 並用規則選擇性定義可用完整權限執行的指令。

在受管理環境中, 管理員可用 admin-enforced requirements 限制這些行為, 例如禁止 approval_policy = "never" 或限制允許的 sandbox 模式。排程任務在組織政策允許時使用 approval_policy = "never", 若管理員規定不允許, 則回退到你所選權限模式的核准行為。

範例

# 自動建立新 skills Scan all of the ~/.codex/sessions files from the past day and if there have been any issues using particular skills, update the skills to be more helpful. Personal skills only, no repo skills.
# 掌握專案最新進度 Look at the latest remote origin/master or origin/main. Then produce an exec briefing for the last 24 hours of commits that touch <DIRECTORY>
# 結合排程任務與 skill 修復自己的錯誤 Check my commits from the last 24h and submit a $recent-code-bugfix.

從任務排程工作的常見情境

追蹤長時間執行的作業
檢查長時間執行的作業直到完成。
輪詢已連接來源
輪詢 Slack, GitHub 或其他已連接來源, 結果保留在同一任務中。
固定節奏提醒
提醒 ChatGPT 以固定節奏繼續一個審查迴圈。
技能驅動的工作流程
執行使用外掛的技能驅動工作流程, 例如檢查 PR 狀態並處理新的回饋。

使用 worktree 可以把排程任務的變更與尚未完成的本機工作隔離, 頻繁的排程可能隨時間累積許多 worktree, 建議封存不需要的執行紀錄, 除非打算保留其 worktree, 否則避免釘選執行紀錄。

Long-running work

為多步驟的工作設定明確的成果與完成準則, 保持聚焦。把相關工作留在同一個任務或對話中, 讓 ChatGPT 能用相同情境決定下一步以及何時完成。

定義完成的意義

Outcome
描述你想要的結果, 而不只是 ChatGPT 該執行的活動。
Constraints
說明需要的工具, 邊界, 相容性需求或應避免的做法。
Verification
加入能證明工作完成的測試, 量測或審查準則。
Migrate this codebase from JavaScript to TypeScript. Preserve existing behavior, compile in strict mode without explicit any types, and make the full test suite pass.

操控進行中的目標

暫停或繼續
在桌面應用程式中, 目標進度列出現在輸入框上方, 可暫停, 繼續, 編輯或清除目標。
補充情境
目標執行期間傳送後續訊息以補充情境或調整限制。
側邊對話
想要狀態摘要或解釋而不打斷主任務時, 使用側邊對話。
預先暫停
預期會失去連線前先暫停目標, 準備好後再繼續。

平行執行多個目標

每個任務保留各自的情境, 訊息, 結果與目標, 可以同時執行多個任務, 但避免讓兩個任務變更相同的檔案, 使用 worktree 讓平行的程式撰寫任務擁有各自的簽出版本。

Notifications

選擇工作需要你關注時如何通知你, 各介面的控制項與傳遞管道不盡相同。

桌面應用程式
在 Settings 選擇回合完成提示要一律不顯示, 只在背景執行時顯示, 或一律顯示, 另有獨立控制項可開關權限與提問通知。
追蹤浮動寵物
浮動寵物可在你於其他應用程式工作時, 另外一種方式追蹤任務活動, 可顯示 Running, Needs input, Ready 或 Blocked。
網頁版
在 Settings > Notifications 管理通知類別與管道, 依類別與帳號可能包含推播, 電子郵件或簡訊, 用 Manage tasks 開啟 Scheduled。
CLI
可選擇 TUI 何時發出通知, 以及回合完成時是否執行外部程式。
IDE 擴充功能
沒有獨立的通知控制項, 保持任務開啟以追蹤活動, 可在已連接的 Codex host 設定 notify 執行外部程式。

Pets

選擇一個動畫夥伴, 並在支援的介面上追蹤任務活動, 選擇寵物只會改變外觀, 不會改變 ChatGPT 完成任務的方式。

寵物狀態意義

狀態意義
Running任務正在積極運作。
Needs input任務需要你的核准, 回答或其他決定。
Ready任務已完成且有未讀活動。
Blocked任務失敗或遇到系統錯誤。

選擇並喚醒寵物

1 · 開啟選單
在應用程式底部的個人選單選擇 Pets, 或開啟 Settings 前往 Pets。
2 · 選擇寵物
選擇內建或自訂寵物。
3 · 喚醒
輸入 /pet, 或開啟指令選單並選擇 Wake Pet。

在 Settings > Pets 或指令選單選擇 Tuck Away Pet, 或再次輸入 /pet 即可隱藏寵物, 重新開啟應用程式時會保留你的選擇與寵物位置。

建立自訂寵物與其他介面

在 Settings > Pets 選擇 Create your own pet, 應用程式會安裝內建的 hatch-pet skill, 重新載入 skills 並開啟新任務, 描述你想要的寵物並送出提示, 任務完成後回到 Settings > Pets 選擇 Refresh 並選用新寵物。桌面版建立的自訂寵物只儲存在本機電腦上, 不會自動同步到 ChatGPT 網頁版。Codex CLI 互動式工作階段中可輸入 /pets 開啟寵物選擇器, /pets <name> 直接選用, /pets off 停用終端機寵物, 終端機寵物需要 iTerm2 3.6 以上版本, 或支援 Kitty graphics 或 Sixel 的終端機, 在 tmux 與 Zellij 中無法使用。Codex IDE extension 目前不提供寵物選擇器或浮動寵物覆蓋層。

寵物會遵循作業系統的減少動態效果設定, 啟用該設定時, 寵物會使用靜態畫格取代精靈動畫。

Codex Micro

你處理 Codex 任務的指揮中心。Codex Micro 是 Codex 與 Work Louder 的限量合作硬體, 可搭配 ChatGPT 桌面應用程式, 讓你快速查看任務, 在任務間切換, 使用一按即說, 並在不離開鍵盤的情況下觸發常見動作或 skills。

設定 Codex Micro

1 · 開啟應用程式
開啟 ChatGPT 桌面應用程式。
2 · 連接裝置
用 USB-C 或藍牙連接 Codex Micro, 並依提示完成設定。
3 · 授權輸入監控
在 macOS 上允許 Input Monitoring, 讓 ChatGPT 能回應按鍵。
4 · 設定按鍵
在 Settings > Codex Micro 選擇 Agent Keys 要追蹤哪些任務, 為 Command Keys 與類比方向指派動作, 並調整燈光。

Browser

讓 ChatGPT 研究並與網站互動。Browser 在 Codex CLI 或 Codex IDE extension 中不可用, 需開啟 ChatGPT 桌面應用程式使用內建瀏覽器, 在網頁版與桌面應用程式中都可以使用。

重要

把頁面內容視為不受信任的情境, 在分享敏感資訊或允許 ChatGPT 採取行動前, 先審視網站與提議的動作。

Computer Use in the Browser

Computer Use 讓 ChatGPT 直接操作內建瀏覽器, 可以開啟頁面, 點擊, 輸入, 檢視渲染狀態, 截圖並驗證頁面中的工作結果。在桌面應用程式打開 Plugins Directory 安裝 Browser, 之後請 ChatGPT 在任務中使用瀏覽器, 或直接以 @Browser 參照。

Use the browser to open http://localhost:3000/settings, reproduce the layout bug, and fix only the overflowing controls.

預覽頁面的步驟

1 · 啟動開發伺服器
在整合終端機或本機環境動作中啟動。
2 · 開啟頁面
點擊網址或手動導覽開啟本機路由或公開頁面。
3 · 對照程式碼差異檢視
將渲染狀態與程式碼 diff 並列檢視。
4 · 留下瀏覽器註解
在需要修改的元素或區域留言。

Developer mode 與 Cloud browser

Developer mode

搭配 Chrome 與內建瀏覽器中的 Computer Use, 讓 ChatGPT 受控存取 Chrome DevTools Protocol, 用於側寫 JavaScript, 檢視主控台與網路流量, 檢查 DOM 與樣式。需在 Settings > Browser 開啟 Enable full CDP access, 使用前 ChatGPT 會要求明確核准。

Cloud browser

在 ChatGPT Work 網頁版中, 讓 ChatGPT 使用雲端代管的瀏覽器研究並與公開網站互動, 與你裝置上的瀏覽器分開執行, 不會存取你的分頁或個人瀏覽紀錄。

限制

僅限公開網站
支援公開, 未登入的網站, 無法登入帳號或使用你瀏覽器中已登入的工作階段。
部分網站受阻
部分網站封鎖自動化瀏覽器或需要 CAPTCHA。
與裝置瀏覽器分開
無法使用你的已開啟分頁, 擴充功能, 已儲存密碼或本機瀏覽紀錄。

Computer Use

讓 ChatGPT 在工作時使用桌面應用程式。在支援的地區, ChatGPT Work 與 Codex 中的 Computer Use 於 macOS 與 Windows 上可用, 需安裝 Computer Use 外掛, macOS 上需在提示時授予 Screen Recording 與 Accessibility 權限。

適合使用的情境

測試桌面應用程式
測試 macOS 應用程式, Windows 應用程式, iOS 模擬器流程或其他正在建置的桌面應用程式。
需要瀏覽器的任務
執行需要你的網頁瀏覽器的任務。
重現圖形介面才會出現的錯誤
重現只在圖形使用者介面才會出現的錯誤。
變更需要點擊介面的設定
變更需要點擊操作 UI 才能完成的應用程式設定。
檢視沒有外掛的資料來源
檢視沒有外掛可用的應用程式或資料來源中的資訊。

在 Windows 上, Computer Use 於前景運作, 執行任務時會接管前景, 建議保持裝置解鎖並連線, 或在 Windows 虛擬機器中執行 ChatGPT 桌面應用程式, 讓 Computer Use 接管虛擬機器而非主要桌面。

設定 Windows 應用程式政策

[computer_use.windows] always_allowed_app_ids = ["mspaint.exe"]

此設定儲存在 $CODEX_HOME/config.toml 中, 列出的應用程式可以不經詢問直接開啟, 管理員可在 requirements.toml 中以 [features].computer_use = false 停用 Computer Use。

Locked use 的防護措施

用途

只適用於 macOS, 讓 ChatGPT 在你的 Mac 鎖定後, 仍能從已連接裝置使用 Computer Use, 需先啟用, 啟用後 ChatGPT 會安裝一個參與 macOS 解鎖流程的 Apple 授權外掛。

防護措施

授權視窗僅短暫有效並限定於當次解鎖嘗試, 自動解鎖只在進行中且受信任的 Computer Use 回合期間可用, 解鎖期間 ChatGPT 會遮蔽所有螢幕, 若偵測到本機鍵盤或滑鼠輸入, 會重新鎖定並暫停自動解鎖直到你手動解鎖。

保持任務範圍狹窄, 敏感流程時親自在場, 隨時可以停止任務或接管電腦, 涉及帳號, 安全, 隱私, 網路, 付款或憑證相關設定時務必親自在場。

Troubleshooting

常見問題與疑難排解方式。

側邊面板出現非 Codex 編輯的檔案 移除側邊欄專案 尋找已封存任務 側邊欄只顯示部分任務 程式碼在 worktree 上無法執行 未套用同事分享的本機環境 Codex 要求存取 Apple Music 排程任務建立太多 worktree 選錯目標後救回提示 CLI 可用但桌面應用程式不可用

當你的專案位於 Git 儲存庫中時, 審查面板會依 Git 狀態自動顯示變更, 包含非 Codex 造成的修改, 你可以切換暫存與未暫存變更, 或與 main 分支比較, 只想看最後一次 Codex 回合的變更時切換到 Last turn 檢視。

將滑鼠移到專案名稱上, 點擊三點選單並選擇 Remove, 之後可用 Add new project 按鈕或按 Cmd+O 還原。

透過 Settings 存取已封存的任務, 取消封存後會還原到原本的側邊欄位置。

選擇 Tasks 旁的篩選圖示並選擇 Chronological, 若任務仍缺漏, 檢查 Settings 中的已封存任務。

Worktree 會繼承 Git 追蹤的檔案, 但可能需要透過本機環境設定腳本, 或用 .worktreeinclude 複製被忽略的檔案, 也可以改在一般專案的簽出中處理變更。

本機環境設定必須位於專案根目錄的 .codex 資料夾中, 對 monorepo 而言, 需開啟包含該 .codex 資料夾的特定專案目錄。

Codex 可能需要瀏覽檔案系統, 而部分 macOS 目錄, 例如 Music, Downloads, Desktop 需要使用者核准, 核准家目錄存取權即可解決。

封存不需要的排程執行紀錄, 除非打算保留其 worktree 否則避免釘選, 頻繁的任務會隨時間累積 worktree。

若不小心選錯目標, 例如 Local, Worktree 或 Cloud, 取消目前的執行, 並在輸入框按上方向鍵救回你的提示。

不同介面可能封裝不同的 Codex 版本, 實驗性功能有時會先出現在 CLI, 可用 codex --version 檢查版本, 桌面應用程式的封裝版本則可用 /Applications/Codex.app/Contents/Resources/codex --version 檢查。

卡住狀態與終端機問題

任務卡住
檢查是否有待核准項目, 執行基本終端機指令如 git status, 或開始一個聚焦的新任務。
終端機卡住
關閉終端機面板, 用 Ctrl+` 重新開啟, 執行 pwd 或 git status 等基本指令確認目錄與分支。
字型顯示異常
在 Settings 的 Code font 設定字型, Codex 會在審查面板, 終端機與程式碼顯示中一致套用。
